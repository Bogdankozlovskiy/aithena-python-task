# LLM evaluations

These evaluations use `gpt-5.4-mini-2026-03-17` directly, without an LLM judge.
The initial seven experiments made 210 API calls; all reports, including failed baseline
responses, are preserved. Their estimated cost was $0.1627, using the recorded rates of
$0.75/$4.50 per million input/output tokens without cache discounts. These are usage-based
estimates, not billing statements. Follow-up v3 and GitHub runs are additional.

## Methodology

- `analysis.json`: 30 cases, comprising the three original files and 27 synthetic cases
  prepared by Codex. There are 20 development cases and 10 holdout cases; holdout responses
  were not used for prompt tuning.
- `translation.json`: five small programs with predefined Rust assertions, covering addition,
  signed division/remainder with both divisor signs, clamp, range, and absolute value.
- Expected results were fixed before API runs, not generated by the evaluated model.
  They have not received independent human review. Python AST and JavaScript Tree-sitter
  additionally verify function lists.
- Analysis uses exact field comparison after normal license normalization. Raw responses
  are retained; one wrong field fails the complete response.
- Translations compile and execute assertions in separate resource-limited containers
  without network, API keys, or host files. License notice preservation is checked too.
- Analysis repeatability means identical JSON across repeats. Rust byte-for-byte
  repeatability and behavior correctness are measured separately.
- Prompts/datasets have SHA-256 identifiers and the model snapshot is pinned. Each request
  uses an independent context; application response caching is disabled.

## Historical results

| Prompt / settings | Exact analysis responses | Rust behavior checks |
|---|---:|---:|
| v1, provider defaults | 38/40 | 8/10 |
| v2, provider defaults | 39/40 | 15/15 |
| v2, temperature=0, reasoning_effort=none, development | 60/60 | 15/15 |
| Same settings, holdout | 30/30 | Not run |
| v2, subsequent GitHub CI | 90/90 | 14/15 |
| v3, local translation regression | Not run | 25/25 |
| v3, subsequent GitHub CI | 90/90 | 15/15 |

The initial selected v2 configuration produced identical JSON for 30/30 cases over three
repeats and identical Rust text for 4/5 cases. Baseline analysis was repeatable for 20/20
cases despite one consistently incorrect answer. Repeatability is not accuracy.
The subsequent successful v3 CI run produced identical analysis JSON for 30/30 cases,
but identical Rust text for only 3/5 cases, despite all behavior checks passing.

## Failures and prompt revisions

1. v1 lost an explicit `MIT OR GPL-3.0-only` expression. v2 preserves the expression while
   retaining category `unknown`, so the application does not automatically select a branch.
2. v1 translated Python `//` directly into Rust `/`, breaking negative-number behavior.
   v2 described floor rounding, remainder signs, and negative divisors.
3. v2 with provider defaults once classified JavaScript as Python because of a `.py`
   extension. The error did not recur in the temperature-zero experiments; independent
   parser verification remains necessary.
4. Instructions clarified notice scope, copyright-holder deduplication, empty files,
   named JavaScript expressions, anonymous functions, and destructured parameters.
5. GitHub CI exposed the signed-division regression again in v2 (14/15 translations).
   v3 retains analysis instructions and adds the explicit quotient/remainder correction
   algorithm. Failed reports remain in `reports/github-v2-*.json`.

The runtime and CI use **v3**, `temperature=0`, and `reasoning_effort=none`.
`prompts-v1.json` and `prompts-v2.json` preserve historical instructions.
The current prompt lives only in `solution/prompts-v3.json`, shared with production.
Historical scores do not guarantee future results.

## Reproduction (paid API calls)

Run from the project root using Python 3.13. Keep credentials outside reports:

```bash
uv sync --frozen --python 3.13
docker build --target rust-validator -t aithena-rust-validator:local .
docker build --target python-reference -t aithena-python-reference:local .
uv run python -m evals.run --env-file /path/to/private.env \
  --prompt-version current --settings temperature-zero --split all --repeats 3 \
  --output evals/reports/my-analysis.json
uv run python -m evals.run --env-file /path/to/private.env \
  --prompt-version current --settings temperature-zero --kind translation --repeats 3 \
  --output evals/reports/my-translation.json
```

For the baseline, select `--prompt-version v1 --settings baseline`. Workers are limited
to 1–4 and repeats to 1–10; defaults are three each. Schema retries allow up to two calls
per case, with additional SDK transport retries. A nonzero exit code indicates failure.
PR CI validates dataset schemas/expected results offline. Pushes to `main`, including
merges, and manual runs on `main` additionally execute paid evaluations.

## Determinism and limits of evidence

A fixed model snapshot and temperature zero do not guarantee deterministic service output.
Thirty small files do not represent all repositories. Repeated responses are correlated;
90/90 must not be interpreted as guaranteed accuracy on unseen data.

Translation checks cover simple integer programs in the signed i64 domain. They do not
establish full equivalence for Python arbitrary-precision integers, exceptions, floats,
complex objects, dependencies, or side effects. Future cases must cover these explicitly
or require unsupported translations to be rejected.

If identical repeated output is required, cache validated results by source hash, prompt
version, model snapshot, and settings. Such a cache preserves a result without proving its
correctness; caching is excluded here so model variability remains visible.

## Dataset expansion

The next useful dataset would contain 200–300 independently labeled files, a separate
holdout split by repository/template family, and documented provenance for every example:

- [SPDX License List](https://github.com/spdx/license-list-data): standard notices and
  license versions, including complete license text rather than only short SPDX headers.
- [ScanCode](https://scancode-toolkit.readthedocs.io/en/stable/how-to-guides/how-to-add-new-license-detection-rule.html):
  notices, compound expressions, and ambiguous fragments. Manually reconcile its expected
  expressions with this application's more conservative contract.
- [Tree-sitter corpus](https://tree-sitter.github.io/tree-sitter/cli/test.html): JavaScript
  syntax edge cases, computed methods, nested generators, destructuring/default/rest
  parameters, and independently verified counts.
- Authorized, anonymized source: long files, repeated notices, malformed code, and embedded
  instructions in comments/strings, with permissions and provenance recorded.
- Metamorphic checks: extension changes, whitespace, CRLF/BOM, relocated comments, and
  added calls without definitions should preserve the relevant metadata.
- Translation checks: independent Python/Rust differential testing, generated inputs,
  range boundaries, empty collections, Unicode, exceptions, and explicit unsupported cases.

These external corpora are proposed sources; they are not imported into the current 35 cases.
See also [evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

Dataset provenance descriptions were clarified after the initial runs; cases and expected
answers were unchanged. Reports retain `dataset_sha256_at_run`, the updated hash, and an
explanation of the metadata-only change.


## Differential Python/Rust checks

Each newly generated translation is also tested against results obtained by running the
original fixture on Python 3.13 in an isolated container. Inputs combine explicit signed-i64
boundaries with 100 pseudorandom samples using seed 20261102. Counts per round: add 167,
division/remainder 440, clamp 333, range sum 107, absolute value 110 (1,157 total).

The supported domain excludes addition overflow, absolute value of i64 minimum, and
minimum divided by -1 (including remainder, whose Rust intermediate quotient overflows).
Range inputs are capped at 1,000 for execution time; negative inputs include i64 minimum.
Clamp tests use ordered bounds. Division by zero is checked as Python ZeroDivisionError
versus Rust panic, not as identical exception types. This is a bounded equivalence check,
not proof of full Python semantics. Evaluation harnesses and generated input batches are not included in model requests;
the translation prompt itself contains illustrative semantic examples.

Reports record the input-generation seed, runner hash, dataset hash, and number of comparisons.
Offline Docker CI tests both correct hand-authored Rust and deliberately wrong translations;
a failing reference run or unsupported case fails the evaluation rather than silently skipping it.

`--security` selects six synthetic adversarial analysis cases, with exact expected metadata.
They are separate from the original analysis development/holdout split. Paid main-branch CI
runs each three times. See [security boundaries](../SECURITY.md).

## Frozen translation holdout

`translation-holdout.json` was committed as `746053f` before the first model call.
It contains three new synthetic programs: Euclidean GCD, factorial, and sign classification.
The current prompt was not adjusted against these cases. These are not external real-world
files and have not been independently human-reviewed. Once inspected, this set is a frozen
regression set; future tuning requires a new untouched holdout.

Run with `--kind translation --split holdout`. Per round, it checks 200 GCD inputs
(excluding i64 minimum because absolute value overflows), factorial inputs 0 through 20,
and 111 signed-boundary/seeded sign inputs. The first run passed 9/9 translations and
996 input comparisons over three repeats; Rust text was not identical across repeats.
See `reports/translation-holdout-first.json`. CI keeps evaluating this set separately.
