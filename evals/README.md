# LLM evaluations

Проверка настоящего `gpt-5.4-mini-2026-03-17`, без модели-судьи. Сохранены все семь
экспериментов, включая неудачные baseline-ответы; всего 210 обращений к LLM.
Расчётная стоимость без скидки за кэш — **$0.1627** по ставкам $0.75/$4.50 за 1M
входных/выходных токенов. Это оценка по возвращённому usage, не банковское списание.

## Методика

- `analysis.json`: 30 кейсов, из них 3 исходных файла и 27 синтетических примеров, подготовленных Codex.
  20 development-кейсов и 10 holdout-кейсов. Ответы holdout не использовались для настройки.
- `translation.json`: 5 небольших программ с заранее заданными Rust assertions.
  Проверяются сложение, деление/остаток с обоими знаками делителя, clamp, range и absolute.
- Эталонные значения зафиксированы Codex до API-прогонов, а не получены от проверяемой
  модели. Независимую человеческую проверку они ещё не проходили.
  Списки функций дополнительно проверяются Python AST и JavaScript Tree-sitter.
- Анализ оценивается точным сравнением всех полей после штатной нормализации лицензии.
  Сырые ответы также сохранены. Ошибка одного поля означает FAIL всего ответа.
- Переводы компилируются и запускаются с assertions в отдельном контейнере без сети,
  ключей и файлов хоста, с лимитами ресурсов. Дополнительно проверяется сохранение notices.
- Повторяемость анализа — одинаковый JSON одного кейса во всех повторах.
  Для Rust отдельно измеряется побайтовая повторяемость и прохождение поведенческих тестов.
- Промпты и dataset имеют SHA-256; версия модели фиксирована. Каждый запрос имеет
  отдельный контекст. Кэш ответов приложения не используется.

## Результаты

| Промпт / параметры | Анализ: точные ответы | Rust: поведенческие проверки |
|---|---:|---:|
| v1, параметры провайдера по умолчанию | 38/40 | 8/10 |
| v2, параметры провайдера по умолчанию | 39/40 | 15/15 |
| v2, temperature=0, reasoning_effort=none, development | 60/60 | 15/15 |
| Те же выбранные параметры, holdout | 30/30 | Не запускался |

Выбранная конфигурация: **90/90 анализов**, одинаковый JSON у **30/30 кейсов** за три
повтора; **15/15 переводов** прошли заданные поведенческие проверки. Текст Rust полностью
совпал между тремя повторами у **4/5 кейсов**, у одного различался, несмотря на верное поведение.
Baseline-анализ был повторяемым у 20/20 кейсов, но один из них стабильно давал неверный ответ.
Следовательно, повторяемость нельзя подменять точностью.

## Найденные ошибки и изменения

1. v1 терял явно записанное `MIT OR GPL-3.0-only`. v2 сохраняет явное SPDX-выражение,
   но оставляет категорию unknown: приложение не выбирает ветку автоматически.
2. v1 переводил Python `//` в Rust `/`, нарушая результат для отрицательных чисел.
   v2 явно описывает округление вниз, знак остатка и отрицательный делитель.
3. v2 со стандартной выборкой один раз назвал JavaScript-файл Python из-за расширения `.py`.
   В повторных проверках с temperature=0 эта ошибка не воспроизвелась; это наблюдение,
   а не доказательство, что она больше никогда не возникнет. Парсер остаётся обязательным.
4. Уточнены область действия notices, дедупликация правообладателей, поведение пустого
   файла, именованные JS expressions, анонимные функции и параметры-деструктуризации.

`solution/llm.py` теперь использует v2, temperature=0 и reasoning_effort=none по умолчанию.
`prompts-v1.json` и `prompts-v2.json` сохраняют сравниваемые версии.

## Повторный запуск (платные API-запросы)

Из корня проекта; ключ хранится вне отчётов:

```bash
docker build --target rust-validator -t aithena-rust-validator:local .
uv run python -m evals.run --env-file /path/to/private.env \
  --prompt-version v2 --settings temperature-zero --split all --repeats 3 \
  --output evals/reports/my-analysis.json
uv run python -m evals.run --env-file /path/to/private.env \
  --prompt-version v2 --settings temperature-zero --kind translation --repeats 3 \
  --output evals/reports/my-translation.json
```

Чтобы воспроизвести baseline, используйте `--prompt-version v1 --settings baseline`.
`--workers` ограничен 1–4; `--repeats` — 1–10. Один кейс допускает до двух вызовов
из-за retry схемы, дополнительно SDK может повторять транспортный запрос. По умолчанию
используются три workers и три повтора. В стандартном CI выполняется только бесплатная
проверка схем/эталонов; реальные evals запускаются явно. Ненулевой exit code означает FAIL.

## Детерминированность и пределы доказательства

Нельзя гарантировать детерминированность сервиса LLM даже при temperature=0 и фиксированной
версии. На данном наборе наблюдалась повторяемость JSON и правильное поведение, но
30 небольших файлов не представляют все реальные репозитории. Повторы коррелированы;
нельзя интерпретировать 90/90 как гарантию 100% точности на новых данных.

Переводы проверены только для простых целочисленных программ в области signed i64.
Нельзя обещать полную эквивалентность Python arbitrary precision, исключений, float,
сложных объектов, зависимостей и побочных эффектов. Будущие кейсы должны включать это
явно либо фиксировать отказ от неподдерживаемой трансляции.

Требование абсолютно одинакового результата повторного обращения следует обеспечивать
кэшем проверенного результата по hash исходника + версии промпта + snapshot модели + параметрам.
Такой кэш закрепляет результат, но не доказывает его правильность. Он не включён в эти
эксперименты, чтобы не скрывать вариативность модели.

## Как расширять dataset дальше

Следующий разумный набор — 200–300 независимо размеченных файлов, с отдельным holdout,
разделением по репозиториям/семействам шаблонов и фиксацией происхождения каждого примера:

- **SPDX License List**: стандартные тексты и идентификаторы в JSON/text. Использовать
  разные notices и версии лицензий, а не только короткий SPDX-header.
  Источник: https://github.com/spdx/license-list-data
- **ScanCode**: notices, составные выражения и неоднозначные фрагменты. Его правила
  сопоставляют текст с license expression; результаты следует вручную сверять с нашим
  более консервативным контрактом, не копировать как безусловный oracle.
  Источник: https://scancode-toolkit.readthedocs.io/en/stable/how-to-guides/how-to-add-new-license-detection-rule.html
- **Tree-sitter corpus**: синтаксические крайние случаи для JS. На их основе создавать
  примеры с independently verified counts: computed methods, nested generators,
  destructuring/default/rest, современные конструкции.
  Источник: https://tree-sitter.github.io/tree-sitter/cli/test.html
- **Собственные обезличенные исходники**: реальные длинные файлы, многократные notices,
  повреждённый код, инъекции в строках и комментариях. Сохранять разрешение/происхождение.
- **Метаморфные проверки**: смена расширения, пробелов, CRLF/BOM, перенос комментария,
  добавление вызовов без определений — метаданные должны оставаться прежними.
- **Перевод**: независимые differential tests Python/Rust, генерируемые входные значения,
  границы диапазонов, пустые коллекции, Unicode, исключения и явные unsupported cases.

Внешние корпуса изучены как источники следующего этапа; в текущие 35 кейсов они не импортированы.
Общие рекомендации по оценке вариативных моделей:
https://developers.openai.com/api/docs/guides/evaluation-best-practices

После прогонов уточнено только описание происхождения dataset; кейсы и эталоны не менялись.
В отчётах сохранён исходный `dataset_sha256_at_run`, новый hash и пояснение изменения метаданных.
